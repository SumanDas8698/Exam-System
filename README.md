# Online Exam System

A complete rebuild of the exam system into three clear sections — **Student**, **Exam**, **Admin** — with proper password hashing, an exam-booking approval workflow, and a calm, elegant "academic ledger" visual theme.

Stack: PHP (mysqli, prepared statements throughout), MySQL, Bootstrap-free custom CSS, vanilla JavaScript.

---

## 1. Setup

### 1.1 Database
1. Open phpMyAdmin (or the MySQL CLI) and import `database.sql`. This creates the `exam_system` database and all tables, plus 4 sample faculties (SUDIPTA DEY, ARUP KARMAKAR, SUMAN DAS, RANAJIT ROY).
2. Edit `includes/db.php` if your MySQL username/password/host differ from `root` / `manager` / `localhost`.

### 1.2 Create your first Admin account
Password hashes must be generated by *your* server's PHP, not copy-pasted from elsewhere — so:

1. Visit `http://localhost/your-folder/setup_admin.php` in your browser.
2. Fill in a username, email, and password (min 8 characters).
3. Submit. Your admin account is created with a correctly verified `password_hash()`.
4. **Delete `setup_admin.php`** afterward (or at least restrict access to it) — it's a one-time bootstrap tool, not meant to stay live.

After that, all further admins can self-register at `/admin/register.php` using the invite code set in that file (`ADMIN_INVITE_CODE`, currently `EXAM-ADMIN-2026` — change this before going live).

### 1.3 Folder structure
```
/
├── index.php                 Landing page
├── setup_admin.php           One-time bootstrap (delete after use)
├── database.sql              Full schema + sample faculty data
├── includes/                 Shared PHP (db, config, header, footer, SimpleXLSX libs)
├── assets/css/style.css      Design system (all styling lives here)

```

## 2. The three sections

### Student
- `register.php` — create account (name, email, course, hashed password)
- `login.php` — email + password login
- `forgot_password.php` / `reset_password.php` — token-based reset (30-min expiry)
- `dashboard.php` — stats + quick links
- `book_exam.php` — pick a faculty, submit a request
- `my_requests.php` — track Pending / Approved / Rejected / Used status; "Start Exam" appears once approved
- `my_results.php` — full result history + certificate links
- `logout.php`

### Exam (only reachable once a request is Approved)
- `start_exam.php` — validates the approved request, blocks duplicate same-day attempts, checks the question bank isn't empty
- `exam.php` — timer, randomized questions, tab-switch malpractice detection, disabled F12/Ctrl+S/etc.
- `submit_exam.php` — scores the attempt, writes `results` + `student_answers`, marks the request `Used`
- `exam_result.php` — immediate pass/fail summary
- `certificate.php` — printable certificate (shared with admin's "view certificate" action)

### Admin
- `register.php` (invite-code gated) / `login.php` / password reset
- `dashboard.php` — live counts: students, pending approvals, exams taken, question bank size
- `exam_requests.php` — **approve/reject** student booking requests (the new gate before any exam can be attempted)
- `manage_students.php` — search, block/unblock, delete
- `manage_topics.php` — add/edit/delete faculties (modal-based, no more `prompt()` dialogs)
- `manage_questions.php` — full question CRUD with a faculty filter
- `bulk_upload.php` — import questions from a 7-column `.xlsx` (same format as before)
- `review.php` — inspect any student's question-by-question answers; clear a record
- `exam_history.php` — look up a student's full history by ID, with a certificate preview modal
- `faculty_report.php` — per-faculty performance table + Excel export

## 3. What changed from the original code (and why)

| Issue in original | Fix |
|---|---|
| Admin login compared plaintext passwords directly in SQL | Replaced with `password_hash()` / `password_verify()` everywhere — students and admins both |
| `admin.php`: `$students_stmt = $faculties_stmt->fetch_all(...)` — students dropdown was actually populated from the faculty query | Separated into two distinct, correctly-scoped queries |
| `admin.php` "Clear Record" deleted `student_answers` but **never actually deleted the `results` row** (the delete statement was empty) | Added the missing `DELETE FROM results WHERE id = ?` |
| `manage_topics.php` deleted `questions WHERE topic_id = ?` — but the real column is `f_id` | Corrected to `f_id`; faculty deletion also now blocked if the faculty already has exam results, to protect historical data |
| `student_answers` unique-key collisions (`error.txt`: `Duplicate entry 'R01-Q02'`) — caused by result IDs/answer numbering not being recalculated safely on resubmission | New `submit_exam.php` always generates a fresh `result_id` first, then derives answer IDs from the current max in the table, and uses `INSERT IGNORE` as a safety net |
| `get_result.php` had a large block of redundant/contradictory if-statements setting `$is_pass` repeatedly | Collapsed into one clean grade/pass calculation in `submit_exam.php`; certificate page just reads the stored grade |
| No password reset for anyone | Full token-based reset flow added for both students and admins (30-minute expiry, single-use tokens) |
| Students could start any exam instantly, no approval step | New `exam_requests` table + admin approval screen gates every attempt |
| Mixed collation workaround (`COLLATE utf8mb4_unicode_ci`) patched into a JOIN | Not needed — new schema is consistently `utf8mb4_unicode_ci`, so the join works natively |
| Inline `prompt()`-based editing for topics | Replaced with proper modal forms |
| Visual design was default Bootstrap blue/white | New custom "academic ledger" theme (navy + amber on warm paper), no Bootstrap dependency at all |

## 4. Security notes

- All SQL uses prepared statements with bound parameters (verified programmatically — every `bind_param()` call has matching type-string length and argument count).
- Passwords are hashed with PHP's `password_hash()` (bcrypt, cost 10 by default).
- Password reset tokens are cryptographically random (`random_bytes(32)`), single-use, and expire in 30 minutes.
- `includes/` is blocked from direct browser access via `.htaccess`.
- `database.sql` is blocked from direct browser access via `.htaccess`.
- Admin self-registration requires an invite code — change `ADMIN_INVITE_CODE` in `admin/register.php` before deploying, or remove the open registration path entirely once your admin team is set.
- Certificate and result-fragment pages check **ownership**, not just "is someone logged in" — a student can only ever view their own certificate; an admin can view any.

### Before going live, you should also:
- Change `ADMIN_INVITE_CODE` to your own secret (or remove self-registration).
- Delete `setup_admin.php` after creating your first admin.
- Replace the demo-mode password reset (which shows the reset link directly on screen) with real email sending — wire up PHPMailer or similar in `forgot_password.php` for both student and admin versions.
- Update `includes/db.php` with your production database credentials.
- Add a real logo to `images/logo.png` if you want a branded certificate (optional — the current design works without one).

## 5. Default exam rules (unchanged from original intent)
- 30 minutes per attempt (`EXAM_MINUTES` in `includes/config.php`)
- One attempt per faculty per day
- Tab-switch is treated as malpractice and ends the exam immediately
- Grading: A ≥90%, B ≥80%, C ≥70%, D ≥60%, Poor ≥50%, Fail <50%
